# บันทึกสินค้า · Prathan

เว็บบันทึกข้อมูล **สินค้าเข้าใหม่ / สินค้าที่มาแทนรุ่นเดิม** และ **คิวสินค้าที่รอถ่ายรูป** พร้อมแนบรูปภาพหลายรูปต่อรายการ
ข้อมูลทั้งหมดเก็บใน IndexedDB บนเครื่องผู้ใช้ — ไม่มี backend ไม่มีค่าเซิร์ฟเวอร์ ใช้งานออฟไลน์ได้

---

## ไฟล์ในโปรเจกต์

| ไฟล์ | หน้าที่ |
|---|---|
| `index.html` | โครงหน้าจอ + CSS ทั้งหมด |
| `schema.js` | **นิยามฟิลด์ข้อมูล** — เพิ่ม/ลบฟิลด์แก้ที่ไฟล์นี้ที่เดียว ฟอร์ม/การ์ด/CSV เปลี่ยนตามเอง |
| `db.js` | ชั้นเก็บข้อมูล IndexedDB (products / images / meta) + จุดต่อ backend ในอนาคต |
| `app.js` | ตรรกะหน้าจอ: ฟอร์ม, ค้นหา/กรอง, คิวถ่ายรูป, ระบบรูปภาพ, export/import |
| `sw.js` | Service Worker — เปิดใช้ออฟไลน์ + ดึงเวอร์ชันใหม่ให้อัตโนมัติ |
| `manifest.json` | ทำให้ติดตั้งเป็นแอปบนมือถือได้ (Add to Home Screen) |
| `build.mjs` | รวมทุกอย่างเป็นไฟล์เดียว → `dist/product-log.html` |

**ไม่มี** React · ไม่มี build step บังคับ · ไม่มี npm · ไม่มี backend

---

## วิธีใช้ 2 แบบ

### 1) ไฟล์เดียว (เริ่มใช้ได้เลย)
เปิด `dist/product-log.html` ด้วย Chrome → ใช้งานได้ทันที
ข้อมูลผูกกับ **ที่เก็บไฟล์** ฉะนั้นอย่าย้ายไฟล์ไปโฟลเดอร์อื่น (ถ้าย้าย ให้ส่งออกไฟล์สำรองก่อน)

### 2) GitHub Pages (แนะนำสำหรับใช้จริงบนมือถือ)
1. สร้าง repo ใหม่บน GitHub (public หรือ private ก็ได้ ถ้ามี Pages)
2. อัปโหลด `index.html`, `schema.js`, `db.js`, `app.js`, `sw.js`, `manifest.json` ไว้ที่ราก repo
3. Settings → Pages → Source = `Deploy from a branch` → branch `main`, folder `/ (root)` → Save
4. รอ 1–2 นาที จะได้ลิงก์ `https://<ชื่อผู้ใช้>.github.io/<ชื่อ repo>/`
5. เปิดลิงก์บนมือถือ → เมนูเบราว์เซอร์ → **เพิ่มไปที่หน้าจอโฮม** → ใช้เหมือนแอป ถ่ายรูปแนบได้ทันที

> แก้โค้ดครั้งต่อไป: อย่าลืมเปลี่ยนเลขใน `sw.js` บรรทัด `const CACHE = 'prathan-product-log-v1'` → `v2`
> ไม่งั้นเครื่องที่เคยเปิดแล้วอาจยังใช้ไฟล์เก่าอยู่

## ฟีเจอร์

**บันทึกสินค้า**
- รหัส/SKU · ชื่อ · แบรนด์ · รุ่น · วันที่เข้า · หมายเหตุ
- ประเภทการเข้า: เข้าใหม่ / **มาแทนรุ่นเดิม** (มีช่องกรอกรุ่นเดิมโผล่ขึ้นมาเอง) / เข้าเพิ่ม
- ค้นหาได้จากทุกช่อง รวมถึงชื่อรุ่นเดิม — ใช้ตอบคำถาม "รุ่นนี้ถูกแทนด้วยอะไร"

**คิวถ่ายรูป**
- สถานะรูป 4 ระดับ: รอถ่ายรูป → ถ่ายแล้ว → อัปโหลดแล้ว (+ ไม่ต้องถ่าย)
- หน้าคิวเรียงตาม **ค้างนานที่สุดขึ้นก่อน** พร้อมป้ายจำนวนวัน (เกิน 7 วันเป็นสีแดง)
- ปุ่มลัด "แนบรูป" / "ถ่ายแล้ว" / "อัปโหลดแล้ว" กดจบในแถวเดียว
- แนบรูปตอนสถานะ "รอถ่ายรูป" ระบบเลื่อนเป็น "ถ่ายแล้ว" ให้เอง

**รูปภาพ**
- เลือกหลายรูปพร้อมกัน หรือลากไฟล์มาวาง
- ย่ออัตโนมัติเป็น JPEG ด้านยาว 1600px + สร้าง thumbnail 420px (ทดสอบแล้วลดขนาดไฟล์ ~80%)
- ตั้งรูปหลัก · ลบรูป · ดูรูปขยาย (ปุ่มลูกศร / Esc) · ดาวน์โหลดรูปเดิม

**ข้อมูล**
- ส่งออกไฟล์สำรอง `.json` (ฝังรูปเป็น base64) → เก็บใน Google Drive หรือย้ายเครื่อง
- นำเข้าแบบ merge — รายการเดียวกันใช้เวอร์ชันที่แก้ไขใหม่กว่า
- ส่งออก `.csv` ตามตัวกรองที่เลือกอยู่ (เปิดใน Excel ได้ ภาษาไทยไม่เพี้ยน)

**คีย์ลัด:** `n` เพิ่มรายการ · `Ctrl/⌘+S` บันทึก · `Esc` ปิด · `← →` เลื่อนรูป

## เผื่ออนาคต: ให้ทีมหลายคนแชร์ข้อมูลกัน

ทุกเรคคอร์ดมี `id` (UUID) · `updatedAt` · `rev` · `deleted` (soft delete) · `dirty` อยู่แล้ว
ซึ่งครบพอสำหรับ two-way sync แบบ last-write-wins

เมื่อพร้อม ให้ implement 3 ฟังก์ชันใน `db.js` → `DB.remote` (`push` / `pull` / `sync`)
แล้วตั้ง `DB.remote.enabled = true` — **ไม่ต้องแก้ `app.js` หรือ `index.html` เลย**

ตัวเลือกที่เข้ากับโครงนี้ง่ายที่สุด:
- **Supabase** — Postgres + storage รูป + auth มี free tier (เหมาะสุดถ้าจะโตต่อ)
- **Firebase Firestore + Storage** — ซิงก์เรียลไทม์ ออฟไลน์เป็นค่าเริ่มต้น
- **Google Apps Script + Sheets** — ถูกที่สุด ทีมดูข้อมูลใน Sheet ได้ตรง ๆ (แต่รูปควรไปอยู่ Drive)

## ข้อจำกัดที่ควรรู้

- ข้อมูลอยู่ใน**เบราว์เซอร์ตัวที่ใช้เปิด** — เปลี่ยนเครื่อง/เปลี่ยนเบราว์เซอร์ ต้อง import ไฟล์สำรอง
- ล้าง "ข้อมูลเว็บไซต์/Site data" ของเบราว์เซอร์ = ข้อมูลหาย → **ส่งออกไฟล์สำรองสม่ำเสมอ**
- โหมดไม่บันทึกประวัติ (Incognito/Private) ข้อมูลหายเมื่อปิดหน้าต่าง
- ไฟล์ **HEIC จาก iPhone** เบราว์เซอร์เปิดไม่ได้ ระบบจะเตือนให้ทราบ
  แก้ที่ต้นทาง: iPhone → ตั้งค่า → กล้อง → รูปแบบ → **"เข้ากันได้มากที่สุด"** (จะได้ JPEG)
